# GDA Ticket Board (Python)

[![CI](https://github.com/kellyfrenchgda/gdaevents/actions/workflows/ci.yml/badge.svg)](https://github.com/kellyfrenchgda/gdaevents/actions/workflows/ci.yml)

Sponsorship ticket and events tracker for Good Drinks Australia.
Flask + SQLite on a Render persistent disk, email/password logins, admin and member roles.

---

## Deploy to Render — what to change

### 1. In the Render dashboard — delete the old service

Your existing service was a Node.js app. The Python app is a clean replacement:

1. Go to your Render dashboard and open the **gda-ticket-board** service.
2. Settings → **Delete service**. Confirm.
3. The persistent disk is attached to that service — delete it too, or it will keep billing.
   Dashboard → Disks → select **gda-data** → Delete.
   *(Or leave it if you want to preserve the event data and re-attach it — the database schema
   is identical.)*

### 2. Create a new Web Service

In the Render dashboard, click **New → Blueprint** and point it at
`kellyfrenchgda/gdaevents`. `render.yaml` will create:

| What | Value |
|---|---|
| Runtime | **Python** |
| Build command | `pip install -r requirements.txt` |
| Start command | `gunicorn wsgi:app --bind 0.0.0.0:$PORT --workers 2 --timeout 120` |
| Instance | Starter ($7/month) |
| Disk | `gda-data` at `/var/data` (1 GB, $0.25/month) |

### 3. Set the environment variables

Before the first deploy, add these in the dashboard under **Environment**:

| Key | Value |
|---|---|
| `FLASK_ENV` | `production` |
| `DATA_DIR` | `/var/data` |
| `SESSION_SECRET` | *(auto-generated by blueprint)* |
| `SEED_DEMO` | `true` for demo events, `false` to start empty |
| `ADMIN_EMAIL` | your work email |
| `ADMIN_PASSWORD` | 10+ characters |
| `ADMIN_NAME` | your name |

Set `ADMIN_EMAIL`, `ADMIN_PASSWORD` and `ADMIN_NAME` yourself — don't commit them.
The admin account is created on first boot only.

### 4. Deploy and sign in

Push to `main` → Render builds and deploys automatically.
Sign in with your `ADMIN_EMAIL` and `ADMIN_PASSWORD`.

**No `NODE_VERSION` needed.** Python has no native-binary compilation issues; the build
just runs `pip install` and that's it.

## Push to GitHub (PowerShell)

Extract the zip somewhere fresh then:

```powershell
cd gdapy
git init -b main
git add -A
git commit -m "GDA ticket board — Python rewrite"
git remote add origin https://github.com/kellyfrenchgda/gdaevents.git
git push -u origin main
```

If the repo already has commits (e.g. a README created on GitHub):

```powershell
git pull --rebase origin main
git push -u origin main
```

Set your identity once if Git hasn't been configured on this machine:

```powershell
git config --global user.name "Kelly French"
git config --global user.email "you@gooddrinks.com.au"
```

## Run locally (Windows PowerShell)

You need Python 3.11+ and Git for Windows.

```powershell
cd gdapy
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env           # fill in the values, save and close
```

Load the `.env` into your session:

```powershell
Get-Content .env | Where-Object { $_ -match '^\s*[^#\s].*=' } | ForEach-Object {
  $name, $value = $_ -split '=', 2
  [Environment]::SetEnvironmentVariable($name.Trim(), $value.Trim(), 'Process')
}
python -m flask --app server.app run --port 3000
```

Open http://localhost:3000 and sign in. Stop with `Ctrl+C`.

To reset the local database:

```powershell
Remove-Item -Recurse -Force .\data
```

## Notes

**No Node.js, no native compilation.** Flask and its dependencies are pure Python or have
binary wheels on PyPI — `pip install` just works on Render without any C++ toolchain.

**Gunicorn workers share the same SQLite file.** Two workers is safe with WAL mode because
SQLite WAL handles concurrent reads and serialises writes. If you scale to more workers,
move to Postgres — the schema ports over cleanly.

**Sessions** are stored in Flask's signed cookie (not the database). They last 12 hours
and are refreshed on activity. The secret rotates on redeploy unless `SESSION_SECRET` is
pinned in the dashboard — pin it so users aren't logged out on every deploy.

**Branch protection** — Settings → Branches on GitHub, require the `test` check.
Render's `autoDeploy` fires on merge without waiting for Actions, so this is what keeps
a failing push off production.
